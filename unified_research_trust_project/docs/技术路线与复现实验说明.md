# 技术路线与复现实验说明

## 1. 项目定位

本项目面向“人机协同情境下的科研决策信任机制研究”。核心任务不是构建一个完全自动化的科研项目审批系统，而是构建一个可解释的 AI 决策支持原型，用于说明专家为什么可以、何时不应当、以及如何校准对 AI 建议的信任。

系统采用“AI 参谋，专家决策”的协同定位：

- AI 输出资助概率、建议结果和解释证据。
- 专家根据解释证据进行采纳、修正、复核或否决。
- 信任校准模块根据置信度、任务风险和偏差审计信号决定是否需要人工重点审查。

## 2. 为什么使用半仿真数据

真实科研资助数据存在三个限制：

1. 公开数据库通常只包含已获资助项目，缺少未获资助项目。
2. 公开数据通常没有完整申请书、专家评分、评审意见和最终排序。
3. 即使使用 OpenAlex、NSF Award Search 或 NIH RePORTER，也需要复杂清洗和匹配，且无法直接得到监督学习标签。

因此本项目采用“半仿真数据为主、公开真实元数据为辅”的策略。半仿真数据用于训练和解释模型；OpenAlex 公开元数据用于证明特征设计具有现实依据。

## 3. 半仿真数据生成机制

每条样本代表一个科研项目申请，包含四类特征。

申请人基础：

- 近五年论文数
- 近五年引用数
- H-index
- 研究年限
- 既往项目数
- 单位层次
- 海外经历
- 年龄阶段

项目质量：

- 创新性评分
- 可行性评分
- 前沿度评分
- 方法成熟度
- 预期影响力
- 经费合理性
- 项目风险
- 数据可得性
- 伦理合规性

团队条件：

- 团队规模
- 跨学科程度
- 合作网络强度
- 平台支撑水平

领域背景：

- 学科类别

隐含资助概率由以下因素共同决定：

```text
资助倾向 =
  申请人科研产出信号
+ 项目创新性、可行性、前沿度、影响力
+ 团队条件和平台支撑
+ 创新性与可行性的交互项
+ 前沿度与跨学科程度的交互项
- 项目风险惩罚
+ 少量背景因素
+ 随机噪声
```

随后使用 sigmoid 函数转化为真实资助概率，并按该概率抽样得到 `funded` 标签。

## 4. 核心模型

实验包含三个模型：

- Logistic Regression：透明线性基线，便于说明传统可解释模型的能力边界。
- Explainable Boosting Machine：主模型，兼顾非线性表达能力和可解释性。
- Random Forest：黑盒预测基线，用于说明准确率不是信任机制的唯一依据。

主模型使用 Explainable Boosting Machine，简称 EBM。其形式可以写为：

```text
logit(P(y=1)) = β0 + f1(x1) + f2(x2) + ... + fij(xi, xj)
```

该模型适合本项目，因为每个特征或特征交互项都有明确贡献，可以导出：

- 全局特征重要性
- 单个项目的局部加分和扣分证据
- 关键变量响应曲线
- 交互项贡献

三类模型形成对比：线性透明模型可解释但表达能力有限；随机森林预测能力强但解释性弱；EBM 能提供非线性响应曲线、全局重要性和局部加减分证据，因此更适合作为人机协同信任机制的核心模型。

## 5. 信任校准与协同分流算法

模型输出资助概率后，系统计算：

- 预测概率
- 置信度：`abs(p - 0.5) * 2`
- 项目风险
- 偏差审计信号：单位层次、海外经历、年龄阶段等背景因素在局部解释中的贡献占比

分流规则：

```text
高置信 + 低风险 + 无明显偏差审计信号：
  快速复核

中等置信或一般风险：
  常规人工复核

低置信、高风险或存在偏差审计信号：
  专家重点审查
```

这体现了信任校准思想：不是让专家无条件相信 AI，而是让专家知道什么时候可以较多依赖 AI，什么时候必须谨慎复核。

## 7. 公开数据映射说明

项目使用 OpenAlex Works API 下载少量真实科研元数据，生成 `data/openalex_reference_sample.csv` 和 `outputs/public_feature_mapping.csv`。

真实字段与仿真特征的对应关系包括：

- `cited_by_count`、`fwci`、`citation_normalized_percentile` 对应科研影响力和引用类特征。
- `authorships`、`institution_count`、`country_count` 对应团队规模和合作网络强度。
- `primary_topic`、`topic_field`、`topic_domain` 对应学科类别、前沿方向和跨学科程度。
- `referenced_works_count`、`related_works_count` 对应研究基础、方法依据和可行性。
- `awards`、`funders` 对应已获资助背景的现实参照。

需要说明的是，OpenAlex 不能提供未获资助申请、评审专家分数和评审意见，因此不能直接替代主训练数据。它在本项目中的作用是支撑特征设计，而不是承担监督学习标签来源。

## 8. 结题汇报可用结论

本项目表明，科研决策中的 AI 信任不应理解为对模型输出的盲目信任，而应理解为基于证据的适当依赖。EBM 模型通过全局重要性、局部贡献和响应曲线，把资助建议拆解为专家可以检查的证据链。协同分流模块进一步把预测置信度、项目风险和偏差审计信号结合起来，使 AI 建议进入不同强度的人工复核流程。

因此，本系统的核心贡献不是提高自动审批率，而是提供一种“可解释、可审计、可校准”的人机协同科研决策机制。
