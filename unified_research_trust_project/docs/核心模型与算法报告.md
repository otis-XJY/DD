# 人机协同情境下科研决策信任机制的核心模型与算法报告

## 摘要

本报告对应课程小组作业中“核心模型和算法”部分，围绕“人机协同情境下的科研决策信任机制研究”这一主题，构建了一个面向科研项目资助评审场景的可解释 AI 决策支持原型。系统并不试图替代专家做最终审批，而是将 AI 定位为科研评审专家的“决策参谋”：AI 输出资助概率、建议结果和解释证据，专家基于这些证据进行采纳、修正、复核或否决。

考虑到真实基金评审数据通常缺少未获资助申请、专家评分和评审意见，本项目采用“半仿真数据为主，公开真实元数据为辅”的数据策略。半仿真数据用于训练监督学习模型和展示解释机制；OpenAlex 真实科研元数据用于证明特征设计具有现实依据。模型层面，本项目比较了 Logistic Regression、Explainable Boosting Machine 和 Random Forest 三类方法，并选择 EBM 作为主模型。EBM 兼具非线性表达能力和玻璃盒可解释性，能够输出全局特征重要性、局部加减分证据和关键变量响应曲线，适合支撑科研评审场景中的信任校准。

实验结果显示，EBM 在 Accuracy、Brier Score 和 Log Loss 上表现较好，同时能提供专家可检查的解释证据链。全局解释结果表明，模型主要依据项目质量因素进行判断，例如创新性评分、项目风险、方法成熟度、跨学科程度和可行性评分。协同分流模块进一步将项目划分为快速复核、常规人工复核和专家重点审查三类，从而形成“预测 - 解释 - 校准 - 复核”的人机协同闭环。

## 1. 研究场景与任务定位

### 1.1 科研决策场景

科研项目资助评审是典型的高不确定性、高专业性和高责任风险决策场景。评审专家需要在有限时间内判断项目的创新性、可行性、研究基础、团队条件、经费合理性和潜在风险。随着科研项目申请数量增加，传统同行评议面临评审负担重、周期长、主观差异大和跨学科识别困难等问题。

AI 决策支持系统可以帮助专家整理信息、识别关键变量、形成初步判断和提示潜在风险。但如果 AI 只给出“建议资助”或“建议不资助”的黑盒结论，专家很难判断其依据是否可靠，容易出现两类信任失衡：

- 过度信任：专家不加复核地采纳 AI 建议，可能放大模型偏差或错误。
- 信任不足：专家因无法理解 AI 逻辑而完全排斥 AI 建议，导致有效信息未被利用。

因此，本项目的核心问题不是单纯提高预测准确率，而是回答：AI 如何以可理解、可审计、可校准的方式辅助科研决策。

### 1.2 系统定位

本系统采用“AI 参谋，专家决策”的定位：

- AI 负责根据结构化特征输出资助概率、建议结果和解释证据。
- 专家负责理解解释证据、判断建议是否合理，并做出最终评审决策。
- 系统根据预测置信度、项目风险和偏差审计信号，将项目分配到不同强度的人工复核流程。

因此，本项目不是自动审批系统，而是一个可解释的人机协同决策支持系统。

## 2. 数据策略

### 2.1 为什么不直接使用真实基金评审数据

真实科研资助评审数据通常难以直接获取。公开数据源如 OpenAlex、NSF Award Search、NIH RePORTER 或 CORDIS 等，可以提供论文、项目、资助方和成果信息，但通常不提供完整的申请书、未获资助项目、专家评分、评审意见和最终排序。对于监督学习而言，缺少未获资助样本和真实评审标签会导致模型训练目标不成立。

如果只使用公开的已资助项目作为正样本，再随意构造负样本，反而会引入更强的数据偏差。因此，本项目采用更稳妥的策略：用半仿真数据承载模型训练和解释演示，用公开真实元数据说明特征设计依据。

### 2.2 半仿真数据生成原则

半仿真数据不是随机造数，而是将科研评审中常见的判断因素转化为显式生成规则。每条样本代表一个科研项目申请，包含申请人基础、项目质量、团队条件和领域背景四类特征。

申请人基础特征包括：

- 近五年论文数
- 近五年引用数
- H-index
- 研究年限
- 既往项目数
- 单位层次
- 海外经历
- 年龄阶段

项目质量特征包括：

- 创新性评分
- 可行性评分
- 前沿度评分
- 方法成熟度
- 预期影响力
- 经费合理性
- 项目风险
- 数据可得性
- 伦理合规性

团队条件特征包括：

- 团队规模
- 跨学科程度
- 合作网络强度
- 平台支撑水平

领域背景特征包括：

- 学科类别

标签生成逻辑如下：

```text
资助倾向 =
  申请人科研产出信号
+ 项目创新性、可行性、前沿度、影响力
+ 团队条件和平台支撑
+ 创新性与可行性的交互项
+ 前沿度与跨学科程度的交互项
- 项目风险惩罚
+ 少量背景因素
+ 随机噪声
```

随后使用 sigmoid 函数将隐含分数转换为真实资助概率，并根据该概率抽样得到二分类标签 `funded`。

该方法有四个优点：

- 可复现：固定随机种子后，数据生成结果一致。
- 可解释：能够说明每个标签背后的生成机制。
- 可控：可以控制资助率、噪声水平、边界样本和风险样本比例。
- 可展示：适合验证解释模型是否能够恢复合理的评审逻辑。

### 2.3 公开真实元数据支撑

项目使用 OpenAlex Works API 下载了 80 条真实科研元数据，并生成 `data/openalex_reference_sample.csv` 和 `outputs/public_feature_mapping.csv`。该数据不用于主模型训练，而用于说明仿真特征与真实科研数据字段之间的对应关系。

主要映射关系如下：

| OpenAlex 字段 | 对应仿真特征 | 解释 |
|---|---|---|
| `cited_by_count`、`fwci`、`citation_normalized_percentile` | `citations_5y`、`expected_impact` | 引用量、领域加权影响和引用分位数可作为科研影响力代理变量 |
| `authorships`、`institution_count`、`country_count` | `team_size`、`collaboration_strength` | 作者、机构和国家数量反映团队规模与合作网络 |
| `primary_topic`、`topic_field`、`topic_domain` | `discipline`、`frontier_score`、`interdisciplinarity` | 主题和领域信息支撑学科类别、前沿方向和跨学科程度 |
| `referenced_works_count`、`related_works_count` | `methodology_score`、`feasibility_score` | 参考文献和相关工作数量可间接反映研究基础和方法依据 |
| `open_access.is_oa`、摘要可得性 | `data_availability` | 开放获取和摘要可得性反映信息可获得程度 |
| `awards`、`funders` | `funded`、`prior_grants` 的现实参照 | 资助奖项和资助方可作为已获资助背景参照 |

这一设计说明：本项目虽然不直接用真实评审数据训练，但特征体系并非凭空设定，而是与真实科研元数据结构相一致。

## 3. 模型设计

### 3.1 模型对比框架

为了说明模型选择的合理性，本项目设置三类模型：

1. Logistic Regression：透明线性基线。
2. Explainable Boosting Machine：主模型。
3. Random Forest：黑盒预测基线。

三者承担不同角色：

- Logistic Regression 用于说明传统透明模型的能力边界。它结构简单、参数可解释，但难以表达复杂非线性关系和特征交互。
- Random Forest 用于代表黑盒集成模型。它通常具有较强预测能力，但缺少天然的、面向专家复核的解释结构。
- EBM 是主模型。它能表达非线性响应和有限交互，同时保留加性结构，适合输出全局和局部解释。

### 3.2 EBM 模型原理

EBM 可以理解为广义相加模型的增强版本。其基本形式为：

```text
logit(P(y=1)) = β0 + f1(x1) + f2(x2) + ... + fij(xi, xj)
```

其中：

- `β0` 是整体基准项。
- `fi(xi)` 表示单个特征对预测结果的贡献函数。
- `fij(xi, xj)` 表示两个特征之间的交互贡献。
- `P(y=1)` 表示模型预测项目获得资助的概率。

该结构的关键优势在于：每个特征或交互项对预测结果的贡献可以被单独展示。对于科研评审专家而言，这意味着 AI 不只是给出结论，还能说明哪些因素提高了资助概率，哪些因素降低了资助概率。

### 3.3 为什么 EBM 适合信任机制研究

信任校准需要专家理解 AI 的能力边界和判断依据。EBM 能支撑以下解释层次：

- 全局解释：模型整体最看重哪些特征。
- 组别解释：项目质量、团队条件、申请人基础等维度分别贡献多少。
- 局部解释：某个具体项目为什么被建议资助或不资助。
- 响应曲线：某个变量变化时，资助概率如何变化。
- 交互解释：两个变量共同变化时是否存在协同效应。

这些解释正好对应科研评审中的不同信任需求：宏观上理解模型价值观，微观上检查个案证据，逻辑上判断变量响应是否符合常识，制度上保留可审计证据。

## 4. 信任校准与协同分流算法

### 4.1 信任校准思想

本项目不追求让专家“更相信 AI”，而是追求“适当依赖 AI”。适当依赖意味着专家对 AI 的信任水平应与模型真实能力、任务风险和解释质量相匹配。

系统为每个项目计算以下信号：

- 预测概率：模型认为项目应被资助的概率。
- 置信度：`abs(p - 0.5) * 2`，越接近 1 表示模型越确定。
- 项目风险：来自项目特征中的风险评分。
- 偏差审计信号：单位层次、海外经历、年龄阶段等背景变量在局部解释中的贡献占比。

### 4.2 分流规则

根据上述信号，系统将项目划分为三类：

| 分流类别 | 规则含义 | 人机协同方式 |
|---|---|---|
| `fast_track` | 高置信、低风险、偏差审计信号较低 | 可进入快速复核流程 |
| `regular_review` | 中等置信或一般风险 | 常规人工复核 |
| `expert_review` | 低置信、高风险或存在偏差审计信号 | 专家重点审查 |

该分流逻辑体现了“AI 不替代专家，而是帮助专家分配注意力”。高置信低风险项目可以提高处理效率；低置信、高风险或存在偏差风险的项目则必须进入更严格的人类审查。

## 5. 实验结果

### 5.1 数据规模

默认实验生成 1500 条科研项目申请样本，资助率约为 25.53%。这一比例接近竞争性科研项目资助场景，既有足够正样本，也保留了大量未资助项目，适合展示边界样本和人工复核需求。

### 5.2 三类模型对比

| 模型 | Accuracy | AUC | Brier Score | Log Loss |
|---|---:|---:|---:|---:|
| Logistic Regression | 0.7067 | 0.7997 | 0.1810 | 0.5346 |
| Explainable Boosting Machine | 0.7813 | 0.7610 | 0.1554 | 0.4755 |
| Random Forest | 0.7653 | 0.7820 | 0.1593 | 0.4884 |

图 1 展示了可视化面板中的三类模型对比。

![模型对比](figures/可视化网站1.jpg)

从结果看，Logistic Regression 的 AUC 最高，说明它在样本排序上有一定优势；但其 Accuracy、Brier Score 和 Log Loss 明显弱于 EBM，说明默认阈值下决策效果和概率校准较差。Random Forest 的 AUC 高于 EBM，但 Accuracy、Brier Score 和 Log Loss 均略弱于 EBM。EBM 在整体决策表现和概率质量上更均衡，同时提供解释证据，因此更适合作为主模型。

这里需要强调：本项目不是单纯的预测竞赛。科研决策信任机制要求模型不仅“预测得出”，还要“解释得清”。EBM 虽然不是所有指标绝对最高，但它能输出全局重要性、局部加减分和响应曲线，因此更符合人机协同需求。

### 5.3 全局解释结果

EBM 全局解释显示，模型最重要的特征包括：

1. 创新性评分
2. 项目风险
3. 方法成熟度
4. 跨学科程度
5. 可行性评分
6. 前沿度评分
7. 预期影响力
8. 合作网络强度
9. 平台支撑水平
10. 既往项目数

图 2 展示了全局特征重要性和特征组贡献度。

![全局解释](figures/可视化网站2.jpg)

从特征组贡献看：

| 特征组 | 贡献占比 |
|---|---:|
| 项目质量 | 53.5% |
| 团队条件 | 19.4% |

这一结果符合科研评审常识：模型主要依据项目质量本身进行判断，而不是过度依赖申请人的背景变量。项目质量占比最高，说明系统的“价值观”集中在创新性、可行性、方法成熟度、前沿度和风险控制上。团队条件和申请人基础也有贡献，但不是决定性因素。学科背景贡献很低，有助于说明模型没有明显偏向某个学科类别。

### 5.4 个案解释结果

图 3 展示了单个项目的局部解释。该项目 `APP-1266` 被模型建议资助，预测资助概率为 0.93551。

![个案解释](figures/可视化网站3.jpg)

局部解释将该项目的决策拆解为加分证据和扣分证据。主要加分项包括：

- 创新性评分
- 项目风险
- 创新性与前沿度交互项
- 前沿度评分
- 方法成熟度
- 跨学科程度
- 创新性与数据可得性交互项
- 预期影响力

主要扣分项包括：

- 团队规模
- 合作网络强度
- 数据可得性
- 学科类别
- 平台支撑水平
- 既往项目数与数据可得性交互项

这种局部解释具有直接的协同价值。专家不需要盲目相信“建议资助”这个结论，而是可以检查证据是否合理。例如，如果专家认为该项目虽然创新性高，但团队规模和合作网络不足确实构成风险，就可以要求进一步论证团队执行能力。如果专家认为某些扣分项不符合领域实际，也可以对 AI 建议进行修正。

## 6. 可视化面板设计

可视化面板由 `app/streamlit_app.py` 实现，面向结题展示和小组内部复现。面板顶部展示样本数、资助率、EBM AUC 和 EBM Brier Score，便于快速了解实验状态。下方包含六个标签页：

1. 模型对比：展示三类模型的指标表和柱状图。
2. 全局解释：展示全局特征重要性和特征组贡献度。
3. 个案证据：选择典型项目，展示加分证据和扣分证据。
4. 响应曲线：展示关键变量变化对资助概率的影响。
5. 协同分流：展示快速复核、常规复核和专家重点审查的分布。
6. 公开数据依据：展示 OpenAlex 真实元数据样例和特征映射表。

该面板的核心作用不是做复杂交互，而是把模型解释结果转化为人类专家可以理解的决策证据。

## 8. 复现方法

在项目根目录创建并激活环境：

```powershell
conda create -p .\.conda python=3.11 -y
conda activate .\.conda
$env:PYTHONNOUSERSITE="1"
pip install -r requirements.txt
```

完整复现实验：

```powershell
python .\src\generate_data.py --n-samples 1500
python .\src\download_public_reference.py --per-page 80
python .\src\train_models.py
python .\src\explain_and_export.py
python .\src\validate_project.py
```

启动可视化面板：

```powershell
streamlit run .\app\streamlit_app.py
```

如果 `validate_project.py` 输出 `Project validation passed.`，说明关键数据、模型、解释结果和公开数据映射均已生成。

## 10. 局限性与改进方向

### 10.1 局限性

1. 主训练数据仍然是半仿真数据，不能声称已经预测真实基金评审结果。
2. OpenAlex 数据只能证明特征设计有现实依据，不能替代真实评审标签。
3. 当前信任校准规则是启发式规则，还没有通过真实用户实验验证。
4. 当前公平性分析只使用偏差审计信号占比，尚未进行更系统的群体公平性检验。
5. 当前面板主要用于展示结果，还没有加入专家反馈保存功能。

### 10.2 改进方向

1. 补充 NSF、NIH 或 CORDIS 公开项目数据，进一步增强真实数据依据。
2. 引入更完整的公平性指标，例如不同单位层次、年龄阶段或海外经历群体之间的分流差异。
3. 增加专家反馈模块，将专家采纳、修正或否决记录保存为后续训练样本。
4. 增加更细粒度的交互解释，重点分析创新性与可行性、前沿度与跨学科程度之间的交互。
5. 设计小规模情境实验，让同学或专家对有解释和无解释的 AI 建议进行信任评分。

## 11. 结论

本项目构建了一个面向科研资助评审的人机协同决策支持原型。系统以 EBM 为核心模型，通过全局解释、局部解释、响应曲线和协同分流，将 AI 的资助建议转化为专家可以理解和审计的证据链。实验结果表明，EBM 在预测表现和解释能力之间取得较好平衡；全局解释结果符合科研评审常识，模型主要依据项目质量进行判断；局部解释能够支持专家对单个项目进行“一案一议”的复核；协同分流模块则将信任校准具体化为不同强度的人工审查流程。

因此，本项目的核心贡献不是提高自动审批率，而是展示一种更适合科研决策场景的“玻璃盒”协同范式：AI 提供建议和证据，专家保留最终判断权，系统通过解释和分流机制促进适当信任。
